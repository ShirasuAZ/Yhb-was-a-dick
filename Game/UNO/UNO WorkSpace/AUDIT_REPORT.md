## 0. 1.1.5 追加变更

本轮在 1.1.4 局域网审计基线上追加以下规则和布局修正；网络连接、房间、重连和权限代码未改变。

### 0.1 手牌过多时的自适应

- 问题：手牌很多时，手牌区按内容撑高，出牌/叠加按钮可能被推到视口外。
- 修复：手牌区固定最大高度并隐藏纵向溢出，手牌行改为可横向滚动；卡牌宽度同时受视口宽度、手牌数量和可用高度限制；操作按钮固定在可伸缩手牌区上方。
- 验证：用实际样式渲染 30 张手牌，在 390×844 和 1280×800 视口下，出牌按钮均在屏幕内，页面无纵向溢出。
- 视觉风格保持原版，仅调整布局约束。

### 0.2 +10 替换 +20

- 卡牌类型由 `wild20` 改为 `wild10`。
- 打出后由服务器随机颜色，下一位摸 10 张并跳过；+10 不参与 +2/+4 叠加。
- 素材改为本地 `plus10.svg`，旧 `plus20.svg` 不再发布；缺少静态资源现在返回 404，不再被 SPA 回退伪装成 200。

### 0.3 +2/+4 连续叠加

- +2 和 +4 进入响应窗口，不再立即结算。
- 下一位可以出任意颜色的 +2/+4 继续叠加；累计值传给下一位。
- 不能或不愿继续时，接受累计摸牌并跳过回合；20 秒无响应自动接受。
- 最后一次为 +4 时可质疑：成立则最后出 +4 者摸累计全部牌，质疑者继续；失败则质疑者摸累计 +2 张并跳过。
- 最后一张为 +2/+4 时按累计值结算后结束对局。

### 0.4 牌库组成

- 4 色各 19 张数字牌：0 一张、1–9 各两张，共 76 张。
- +2、跳过、反转各 8 张，共 24 张。
- 万能变色 4 张、+4 万能 4 张、+10 一张。
- 总计 109 张。

## 1. 项目概况

### 1.1 技术栈与结构

| 层 | 实际实现 |
| --- | --- |
| 前端 | React 19 + TypeScript + Vite |
| 后端 | Node.js + Express 5 |
| 实时通信 | Socket.IO 4，WebSocket 优先、Polling 兜底 |
| 桌面壳 | Electron 44，内置 Express/Socket.IO 服务器 |
| 房间/游戏状态 | 服务器内存中的 `RoomManager` / `UnoGame`，服务器权威 |
| 账号 | 本机 `accounts.json`，scrypt 加盐密码哈希，HMAC 签名令牌 |
| 静态资源 | 本地 SVG 精灵图、+10、牌背，无外部图片热链 |
| 测试 | Vitest 单元/集成 + Playwright 浏览器/桌面端 E2E |

关键模块：

- `server/index.ts`：命令行服务器入口。
- `server/app.ts`：HTTP、Socket.IO、静态资源、LAN 访问控制、探测接口。
- `server/room.ts`：房间生命周期、座位、准备、房主转移、断线重连、幂等操作。
- `server/game/game.ts`：服务器权威规则引擎。
- `server/game/deck.ts`：109 张牌（108 张标准牌 + 1 张 +10）。
- `client/src/session.ts`：账号、房间、会话恢复、Socket 事件。
- `client/src/components/`：登录、大厅、等待页、牌桌、局域网面板。
- `electron/main.ts`：桌面版启动内置服务器、窗口、更新。

### 1.2 启动方式与监听地址

- 开发：`npm run dev`，前端 `:5173`，后端 `:3000`，Vite 代理 `/socket.io` 和 `/api`。
- 生产 CLI：`npm run build` 后 `node dist/server/index.js`；默认 `HOST=0.0.0.0`、`PORT=3000`。
- 桌面版：内置服务器使用 `0.0.0.0`，从 3000 起尝试到 3011，窗口加载 `http://127.0.0.1:<实际端口>`。
- Docker/Render：`HOST=0.0.0.0`，`UNO_LAN_OPEN=1`，公网部署关闭主机网络控制。

### 1.3 通信路径

1. 主机启动服务器。
2. 主机创建房间，等待页显示局域网地址和房间链接。
3. 客人打开 `http://<主机局域网IP>:<端口>/room/<房间号>`，页面、静态资源和 Socket.IO 都从该主机加载。
4. 客户端通过同源 Socket.IO 连接主机；每个玩家只收到自己的手牌，公开状态一致。

## 4. 问题清单与修复

### P0-01：非本机 HTTP 地址下所有操作按钮静默失效

- 严重程度：P0（局域网核心功能被阻断）
- 影响功能：准备、开始游戏、离开房间、出牌、摸牌、结束回合、UNO、+4 响应、再来一局、局域网开关。
- 复现步骤：客人通过 `http://<局域网IP>:3000` 打开页面，加入房间后点击“准备”。
- 实际结果：按钮无请求、无错误提示；浏览器控制台出现 `TypeError: crypto.randomUUID is not a function`。
- 预期结果：通过局域网 HTTP 地址访问时操作正常。
- 根本原因：`crypto.randomUUID()` 只在安全上下文（HTTPS 或 localhost/127.0.0.1）可用；局域网 IP 的 HTTP 页面不是安全上下文。所有动作编号都直接调用了该 API。
- 修改文件：`client/src/actionId.ts`（新增）、`client/src/session.ts`、`client/src/components/WaitingRoom.tsx`、`client/src/components/GameScreen.tsx`。
- 修复方案：新增 `createActionId()`，优先 `randomUUID`，不可用时使用 `crypto.getRandomValues` 生成 UUID；极端环境回退到随机字节。
- 修复后验证：WLAN 页面准备操作 36ms 完成；无 `pageerror`；准备、开局、刷新、摸牌、退出均正常。

### P1-02：离开房间后仍可能被上一房间的延迟状态拉回

- 严重程度：P1
- 影响功能：退出房间后仍显示房间/对局。
- 复现条件：退出前有操作正在进行，服务器广播的 `room_state` 在客户端清空房间后到达。
- 根本原因：客户端收到任何 `room_state` 都无条件写入房间状态，没有过滤已退出的房间。
- 修改文件：`client/src/session.ts`。
- 修复方案：维护 `exitedRoomCodesRef`；退出、房间关闭、账号被接管时记录房间号；收到该房间的延迟状态直接忽略；重新加入同一房间前清除过滤标记。
- 修复后验证：主动退出后稳定停留在大厅；同账号接管后旧设备回大厅。

### P1-03：玩家退出后仍占据牌桌座位

- 严重程度：P1
- 影响功能：玩家退出/弃权后，其他电脑仍看到已退出玩家座位。
- 根本原因：`seatedOpponents()` 使用全部 `room.players` 计算座位，包含 `active:false` 的玩家。
- 修改文件：`client/src/components/seatLayout.ts`、`tests/unit/seat-layout.test.ts`。
- 修复方案：只对 `active` 玩家分配座位，并按活跃人数选择 2–6 人布局。
- 修复后验证：邀客人对局中退出后，主机 `.table-seat` 数量为 0，结束列表只剩主机；新增单元测试通过。

### P1-04：准备按钮显示“取消准备”但玩家列表仍显示“未准备”

- 严重程度：P1
- 影响功能：其他电脑无法可靠准备，房主无法开始。
- 根本原因：旧实现先在本地展示目标准备状态，再等待服务器确认；请求失败或网络延迟时，按钮与服务器列表矛盾，且可能一直处于禁用状态。P0-01 的异常也会让这个状态永久卡住。
- 修改文件：`client/src/components/WaitingRoom.tsx`、`client/src/session.ts`。
- 修复方案：服务器确认前只显示“准备中…”/“取消中…”；服务器状态到达后再显示“取消准备”；确认超时缩短到 5 秒并回滚。
- 修复后验证：WLAN 高延迟/正常路径均无“未准备 + 取消准备禁用”的矛盾状态。

### P2-05：同一账号在第二台设备进入后，旧设备卡在断线房间

- 严重程度：P2（账号共用场景）
- 影响功能：旧设备显示“已断开”但仍停留在房间页面，无法操作。
- 根本原因：服务器接管座位时直接 `disconnect(true)` 旧 Socket，客户端没有接管通知，也不会自动恢复。
- 修改文件：`server/room.ts`、`shared/protocol.ts`、`client/src/session.ts`、`tests/integration/helpers.ts`、`tests/integration/online.test.ts`。
- 修复方案：向旧 Socket 发送 `session_replaced`，将其移出房间但保持连接；客户端收到后清空房间和会话并回到大厅。
- 修复后验证：同账号第二设备接管后，旧设备稳定回到大厅且连接仍为“已连接”；集成测试通过。
- 设计说明：同一账号不是两个玩家，第二台设备会接管原座位；两台设备同时游玩必须使用不同账号。

### P2-06：通过房间号返回时，其他玩家没有收到在线状态更新

- 严重程度：P2
- 影响功能：断线后从大厅用房间号重新加入，其他玩家仍显示其离线。
- 根本原因：`joinRoom` 的已有账号分支只向返回者发送状态，没有广播给房间其他玩家。
- 修改文件：`server/room.ts`。
- 修复方案：已有玩家恢复后调用 `room.emitStates()`。
- 修复后验证：新增集成测试，主机能在返回者重连后看到 `connected:true`。

### P2-07：所有玩家断开后，只有客人重连时房主控制丢失

- 严重程度：P2
- 影响功能：房间没有可用房主，无法开始/再来一局。
- 根本原因：`Room.resume()` 没有重新执行房主转移。
- 修改文件：`server/room.ts`。
- 修复方案：恢复连接后调用 `transferHost()`；新房主自动设为已准备。
- 修复后验证：集成测试覆盖“客人先断、房主后断、客人再重连”，客人恢复为房主。

### P2-08：局域网 HTTP 页面复制按钮失效

- 严重程度：P2
- 影响功能：非安全上下文中复制房间号/链接。
- 根本原因：`navigator.clipboard` 在局域网 HTTP 页面不可用，部分组件直接调用它。
- 修改文件：`client/src/components/WaitingRoom.tsx`、`client/src/components/GameScreen.tsx`，复用 `client/src/clipboard.ts`。
- 修复方案：统一使用带 `textarea + execCommand` 回退的 `copyText()`。
- 修复后验证：WLAN 页面点击“复制房间号”显示“已复制”。

### P2-09：只输入 IP 时固定假设 3000 端口，失败后直接跳空白页

- 严重程度：P1（直接影响 IP 加入）
- 影响功能：主机 3000 被占用、端口变化、局域网关闭、地址错误。
- 根本原因：`ConnectHostPanel` 直接拼 `http://IP:3000` 并导航，没有连通性/服务类型/LAN 开关检查。
- 修改文件：`client/src/connectTarget.ts`（新增）、`client/src/components/ConnectHostPanel.tsx`、`server/app.ts`。
- 修复方案：
  - 只输入 IP 时并行探测 80、3000–3011。
  - 优先 WebSocket 成功的主机。
  - 新增 `/api/join-info`，区分非 UNO 服务、不可达、LAN 关闭。
  - HTTP 403 返回友好页面；API 返回 `LAN_CLOSED` JSON。
- 修复后验证：只输入 `127.0.0.1` 自动找到 3000；WLAN 跨域探测 26.209.70.144 成功；模拟关闭返回明确提示。

### P2-10：局域网关闭时的远程提示不明确

- 严重程度：P2
- 影响功能：用户不知道是服务未启动、IP 错还是局域网未开放。
- 修改文件：`server/app.ts`、`client/src/connectTarget.ts`、`client/src/components/ConnectHostPanel.tsx`。
- 修复方案：API 403 返回 `LAN_CLOSED`；页面 403 展示“请先开启局域网访问”；客户端提示主机等待页操作。
- 修复后验证：模拟远程 403 的集成测试和前端错误提示测试通过。

### P2-11：大厅断线幽灵最长保留 10 分钟

- 严重程度：P2
- 影响功能：关闭页面/断网的客人长时间留在房主玩家列表。
- 根本原因：原本所有阶段统一使用 10 分钟重连宽限。
- 修改文件：`server/room.ts`。
- 修复方案：大厅断线宽限改为 8 秒；对局中仍保留 10 分钟重连窗口。
- 修复后验证：关闭客人页面后主机先看到“离线”，约 8 秒后玩家从列表移除。
- 剩余设计：对局中的断线玩家仍保留 10 分钟座位，这是现有设计。

### P3-12：布尔字段使用 truthy 强制转换

- 严重程度：P3
- 影响功能：恶意/异常客户端可发送字符串 `"false"` 被当成 `true`。
- 修改文件：`server/room.ts`。
- 修复方案：`set_ready` 和 `host_set_lan_access` 只接受严格布尔值；新增 `INVALID_READY` 测试。
- 修复后验证：非布尔准备请求被拒绝，状态不变。

### P3-13：离开玩家的幂等操作记录未清理

- 严重程度：P3
- 影响功能：长期运行房间的 `recentActions` Map 可能积累离开玩家记录。
- 修改文件：`server/room.ts`。
- 修复方案：主动离开、断线移除时删除该玩家记录。

### P3-14：操作者可能漏收广播状态

- 严重程度：P3（已被刷新机制兜底）
- 修改文件：`server/room.ts`、`shared/protocol.ts`、`client/src/components/WaitingRoom.tsx`、`client/src/components/GameScreen.tsx`。
- 修复方案：
  - 每个动作处理完后，服务器把权威状态直接回给操作者的 Socket。
  - 新增 `sync_room` 事件和等待页/牌桌“刷新”按钮，手动重新拉取状态。
- 修复后验证：WLAN 对局中刷新后状态一致；无错误。

## 7. 尚存风险

1. **未完成真实两台物理设备验证**。当前只有一台电脑，WLAN IP 测试仍是同机网络接口；真实设备的 Windows 防火墙、路由器客户端隔离、VPN 路由仍需用户验收。
2. **Windows 防火墙不会自动修改**。首次连接超时，需要在主机防火墙允许 TCP 3000–3011。
3. **同一账号是接管而不是第二个玩家**。两台设备同时游玩请使用两个不同账号。
4. **对局中断线没有回合超时**。若断线玩家正好是当前回合玩家，房间最多可能等待其 10 分钟重连宽限；这是当前设计限制。
5. **服务器重启不保留房间/牌局**。账号保留，但对局状态只在内存中；服务器重启后客户端会回大厅。
6. **HTTP 局域网的密码传输未加密**。请只在可信局域网/加密虚拟局域网使用；公网部署需要 HTTPS/WSS 反向代理。
7. **IPv6 局域网地址未枚举**。当前面板只列 IPv4。
8. **反向代理/HTTPS 场景下 LAN 面板仍生成 HTTP 地址**。公网部署应关闭主机网络控制并使用 `VITE_SERVER_URL`/外部 HTTPS 入口。
9. **登录失败尝试 Map 无全局上限**。大量不同用户名失败可能造成内存增长，属于局域网低优先级 DoS 风险。
10. **真实移动设备未测试**。390px 视口布局通过，但触控、输入法、真实网卡切换未验收。

## 8. 用户操作指南

### 8.1 主机

1. 安装并运行 `UNO-LAN-1.1.5-setup.exe`。
2. 注册/登录账号，创建房间。
3. 等待页点击“开放局域网访问”。
4. 在“首选地址”选择 WLAN/以太网；只有使用 Radmin/UU/小蓝盾时才选对应虚拟网卡。
5. 点击“复制房间链接”，发给其他玩家。
6. 若其他玩家连接超时，在主机 Windows 防火墙允许 TCP 3000–3011。

### 8.2 客人

1. 安装并运行同一个 EXE。
2. 在“连接主机”只输入主机 IP（自动探测 80、3000–3011），或粘贴完整房间链接。
3. 使用**不同于主机**的账号注册/登录。
4. 进入房间后点击“准备”。
5. 主机点击“开始游戏”。

### 8.3 确认确实是同一台主机

- 客人地址栏应为 `http://<主机IP>:<端口>/room/<房间号>`，不能是 `127.0.0.1` 或 `localhost`。
- 两端玩家列表和房间号必须一致。
- 两端当前回合、当前颜色、牌库剩余、弃牌数量应一致。
- 一端出牌/摸牌后，另一端应在下一状态更新中看到相同结果。

### 8.4 断线/刷新

- 等待页和牌桌右上角有“刷新”，可重新拉取服务器权威状态。
- 刷新页面会使用本地保存的房间会话尝试恢复座位。
- 大厅断线 8 秒内可恢复；对局中断线保留 10 分钟重连窗口。
- 主动点击“离开房间”会立即回大厅，并让其他客户端移除该玩家。

### 8.5 连接失败排查顺序

1. 主机是否仍在运行，房间是否仍存在。
2. 是否点击了“开放局域网访问”。
3. 客人地址是否是主机实际 WLAN/以太网 IP，而不是自己电脑的 127.0.0.1。
4. 两台设备是否在同一 Wi-Fi/路由器；路由器是否开启客户端隔离。
5. 是否误用了 Radmin/UU 等虚拟网卡地址；虚拟局域网可作备选，但延迟取决于工具。
6. 主机 Windows 防火墙是否放行 TCP 3000–3011。
7. 主机端口是否因 3000 占用变为 3001–3011；链接是否包含实际端口。
8. 两端账号是否不同（同账号会接管座位）。
