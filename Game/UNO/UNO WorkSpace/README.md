# UNO 在线联机

一个可实际游玩的 UNO 网页游戏，支持 2–6 名玩家通过真实 Socket.IO 服务器联机，并在标准 108 张牌之外加入全局唯一的 +10 随机颜色牌。

## 当前交付状态

- 已实现真实后端、房间系统、服务器权威规则、断线重连和极简前端。
- 已实现真实可开关的“局域网开放”面板，自动列出 WLAN、Radmin、UU、小蓝盾及其他系统网卡地址。
- 等待页和牌桌右上角提供“刷新”按钮，可重新拉取服务器权威状态；每次操作后服务器也会把最新状态直接回给操作者。
- 大厅内断线 8 秒内未重连会释放座位并广播给其他玩家；对局中仍保留 10 分钟重连窗口。
- 已实现用户名密码登录/注册，密码使用 scrypt 加盐哈希，账号保存在运行服务器的电脑上。
- 游戏主界面采用全屏围桌布局：公共牌区居中、对手环绕、自己的手牌固定在底部。
- 手牌采用“先选中、再点击出牌”的两步确认交互。
- Windows 便携版 EXE 内置服务器，无需另开浏览器；输入主机 IP 即可进入对方大厅。
- 已在本地生产构建中通过真实 Socket 客户端测试，以及 Chromium 的两个独立浏览器上下文和六个浏览器上下文测试。
- **当前没有公网部署地址。** 本工作区未配置云主机、域名或部署账号，因此不能声称已经可以跨公网游玩。公网联机需要按下方部署步骤启动服务器，并提供一个外部可访问的 HTTPS/WSS 地址。
- 物理第二台设备尚未在本工作区中接入验证；“不同浏览器”验收使用了两个隔离的浏览器上下文和不同视口。部署到公网后，仍需用一台真实手机/电脑访问公网地址做最终设备验收。

## 技术结构

```text
client/                  React + TypeScript 前端
server/
  game/deck.ts           109 张牌构建、洗牌、牌面匹配
  game/game.ts           独立游戏规则引擎（回合、惩罚、UNO、+10、胜负）
  room.ts                房间、座位、重连、房主转移、Socket 事件
  index.ts               Express + Socket.IO 服务器与静态资源
shared/protocol.ts       前后端共享协议和可见状态类型
tests/unit/              牌库、规则、双人/三人/六人完整对局
tests/integration/       真实 Socket.IO 服务端联机测试
tests/e2e/               两个及六个独立浏览器上下文验收
```

服务器是唯一游戏状态来源。客户端只发送操作意图，不持有权威牌库，也不能决定随机颜色、手牌归属或胜负。

## 本地启动

要求 Node.js 20.19 或更高版本。

```bash
npm install
npm run dev
```

- 前端开发地址：`http://localhost:5173`
- 后端地址：`http://localhost:3000`
- 开发模式下 Vite 会把 `/socket.io` 和 `/api` 代理到后端。

生产模式：

```bash
npm run build
PORT=3000 HOST=0.0.0.0 npm start
```

Windows PowerShell：

```powershell
$env:PORT = "3000"
$env:HOST = "0.0.0.0"
npm start
```

然后访问 `http://localhost:3000`。服务端同时提供前端静态文件和 Socket.IO。

同一局域网内测试时，让另一台设备访问 `http://<本机局域网 IP>:3000`，并确认系统防火墙放行该端口。创建房间后在“局域网开放”面板里选择对应网卡的“复制房间链接”，不要分享仅本机可用的 `127.0.0.1` 地址。

## Android APK

安卓客户端位于 android-client/。它连接电脑上运行的 UNO 服务端，不在手机上启动服务器。打开 APK 后输入主机 IP 或 IP:端口；未填端口时自动检查 80、3000–3011。主机电脑需运行游戏，并在等待页打开局域网访问；手机和电脑需位于同一局域网或可互通的虚拟局域网。

使用 Android SDK、JDK 17 与 Gradle Wrapper 构建 debug APK：

    $env:ANDROID_SDK_ROOT = "E:\Program Files\Android\SDK"
    $env:JAVA_HOME = "C:\Program Files\Java\jdk-17"
    cd android-client
    .\gradlew.bat :app:assembleDebug

APK 输出在 android-client\app\build\outputs\apk\debug\app-debug.apk；本次构建的副本位于 release\UNO-LAN-1.1.7-android-debug.apk。这是可安装的调试签名版本，尚未配置用于商店发布的正式签名。安装要求 Android 7.0（API 24）或更新版本。

网页、Windows 桌面版和 Android 加载的游戏界面均可在右上角选择“跟随系统 / 浅色 / 深色”。默认跟随设备系统主题，手动选择会保存在本机。


输出文件：

```text
release\UNO-LAN-1.2.1-setup.exe
```

安装程序不是一键安装，会显示传统安装向导，可选择“仅当前用户/所有用户”和自定义安装目录，并创建桌面及开始菜单快捷方式。卸载程序默认保留 `%APPDATA%\uno-online\data` 中的账号数据。

EXE 启动后会：

- 在后台启动内置 Express/Socket.IO 服务器并打开桌面游戏窗口。
- 使用 `%APPDATA%\uno-online\data` 保存账号。
- 局域网默认关闭；创建房间后，在等待页手动点击“开放局域网访问”，再查看 Radmin、UU、小蓝盾或 WLAN 地址。
- 其他玩家运行同一个 EXE 后，在大厅输入主机 IPv4 或 `IP:端口` 并点击一次“连接主机”；唯一可加入房间会自动打开，多房间时显示列表供选择。
- 普通局域网和虚拟局域网使用同一 IP 连接流程，不按网段或组网软件限制地址。主机默认监听 `0.0.0.0:3000`；端口冲突时可使用启动时实际端口并输入 `IP:端口`。
- 主机需要先开放局域网访问。Windows 防火墙和虚拟网络是否允许 TCP 通信由实际连接结果决定；主机未启动、地址不可达或端口未开放时不会加入成功。

该 EXE 没有购买代码签名证书，Windows SmartScreen 可能显示“未知发布者”。请只从你信任的项目目录运行。

游戏页面右上角显示当前版本号。桌面版启动时会自动检查更新清单；发现更高版本时弹出“立即更新”提示。

更新清单查找顺序：

1. 环境变量 `UNO_UPDATE_MANIFEST` 指向的 HTTP(S) 地址或本地 JSON 文件。
2. `%APPDATA%\uno-online\update.json`。
3. 已安装 EXE 同目录的 `update.json`。

清单格式参考项目根目录的 `update.example.json`。`downloadUrl` 可以是完整 HTTP(S) 地址、本地安装包路径，或相对清单文件的安装包路径。没有新版本清单或版本不高于当前版本时不会显示伪造提示。

点击“立即更新”后，旧版会退出，辅助进程静默运行新安装包覆盖旧文件，删除下载/本地安装包，然后启动新版本。账号目录 `%APPDATA%\uno-online\data` 不参与清理。

注意：此前已经发布且不包含更新模块的旧 1.0.0 二进制无法自行获得更新能力，必须先手动安装一次 1.1.1 或更高版本。之后只要提供更高版本的 `update.json` 和安装包，就会自动提示并执行上述更新流程。

## 登录与注册

- 首次打开游戏需要注册用户名和密码，之后登录后才能创建或加入房间。
- 用户名允许 2–16 个文字、数字、下划线或短横线；密码至少 8 个字符。
- 密码使用 `scrypt` 加随机盐后保存，账号文件中不存在明文密码。
- 登录令牌使用服务器持久化密钥签名，有效期 7 天；刷新页面会保持登录，并恢复原房间座位。
- 房间座位绑定账号；同一账号在其他设备重新进入同一房间时会恢复原座位，不会重复占座。
- 同一账号同时在两台设备进入同一房间会接管原座位；原设备会回到大厅并提示。需要两台设备同时游玩时，请分别注册两个账号。
- 账号默认保存在 `D:\MyGame\UNO\data\accounts.json`，可通过 `UNO_DATA_DIR` 改为其他持久化目录。
- 当前没有邮箱验证、找回密码或第三方登录，这是单主机局域网版本的有意范围控制。

局域网中登录会通过当前 HTTP 连接发送密码。Radmin、UU 等加密虚拟局域网可以保护这段连接；若通过公网开放，请务必在前面加 HTTPS/WSS 反向代理，不要直接暴露明文 HTTP 端口。

## 牌桌界面

- 游戏页面按 100dvh 使用整个视口，顶部只保留房间号、当前回合、连接状态和退出按钮。
- 中央固定摸牌堆、弃牌顶牌、当前颜色、方向、牌库数量、弃牌数量和一条简短事件提示。
- 自己的手牌固定在底部，卡牌单行排列；手牌多时自动压缩宽度，超出手牌区时允许横向滚动。
- 对手座位根据**相对自己的座位顺序**分配，不使用加入顺序直接铺排；出牌方向变化不会旋转或移动座位。
- 2 人：对手在上方中央。
- 3 人：上方中央 + 左侧。
- 4 人：上方中央 + 左侧 + 右侧。
- 5 人：上方中央 + 左侧 + 右侧 + 下方左侧。
- 6 人：自己占底部中央，另有 5 名对手；实际排布为上方两名、左侧一名、右侧一名、下方左侧一名。需求文字中“上方两名、左右各一名、下方两名对手”相加会变成 6 名对手（总计 7 人），因此按 6 人必须为 5 名对手的数学约束实现。
- 卡牌采用白色外框、彩色内面、白色中央椭圆、色号中心数字和上下角标；万能牌为黑色牌面加四色标识，+10 保留醒目的黑色“+10 WILD”牌面。
- 不添加座位旋转、发光、循环动画或装饰性背景。

## 局域网开放按钮

在运行服务器的本机创建房间后，等待页会显示“局域网开放”面板。初始状态为关闭，必须手动开放。

- 面板会自动枚举本机所有 IPv4 网卡，包括 WLAN、有线网卡、Radmin、UU、小蓝盾、TAP/TUN、Tailscale、ZeroTier 等由系统暴露的虚拟网卡。
- 默认只显示一个“首选地址”选择器、对应房间链接和复制按钮；其他网卡收在默认折叠的“更多网卡”中。
- 首选地址默认使用当前访问地址，否则优先 WLAN/有线；用户选择后会按主机和端口保存到浏览器。
- “连接主机”只需输入目标 IP 并点击一次；唯一可加入的房间自动加入，多房间时从目标主机返回的房间列表中选择。默认端口为 `3000`，支持输入 `IP:端口`。
- 点击“开放局域网访问”后，其他设备可以访问所选地址；点击“关闭局域网访问”后，非本机连接会被拒绝，已连接的远程玩家会断开。
- 如果其他设备连接超时，请在主机 Windows 防火墙中允许 TCP 3000–3011；项目不会自动修改防火墙规则。
- 面板只对运行服务器的本机显示和开放，普通局域网玩家不能更改这个开关。
- 不需要为 UU、小蓝盾或 Radmin 写专门适配器：先在这些工具里加入同一网络，再使用面板里出现的该网卡地址。
- 房间等待页会为每个网卡生成对应的完整房间链接，可直接复制给使用该网络的玩家。
- 本机仍可通过 `127.0.0.1` 访问，因此可以在关闭局域网后继续管理房间。

## 选牌与出牌

- 点击手牌只会选中，不会立即向服务器发送出牌请求。
- 再次点击同一张牌取消选择；点击另一张牌直接切换选择。
- 选中的牌立即上移并显示白色描边，不使用过渡动画。
- 点击底部“出牌”按钮后才正式提交服务器；没有选择或选择不合法时按钮禁用并显示原因。
- 万能牌和 +4 在点击“出牌”后才进入颜色选择；+10 在确认后由服务器随机颜色。
- 摸牌会清除选择；轮到其他玩家或回合状态变化时，过期选择会被清除。
- 不可打出的牌不灰化；是否能出牌由“出牌”按钮和提示文字表达。

## 公网部署

公网网页和独立运行的主机均使用 HTTP API 与 Socket.IO 同源连接。大厅输入目标主机 IP 并点击“连接主机”后，由目标主机验证房间状态；唯一房间自动加入，多个房间显示选择列表。HTTPS 网页连接 HTTP 局域网主机时会直接导航到输入的 IP；默认端口为 `3000`，可输入 `IP:端口`。探测接口为 `/api/join-info`，设置 `UNO_DOWNLOAD_DIR` 可指定 `/downloads` 下载页读取的 Windows、Android 安装包目录。服务端接受 `HOST`、`PORT`、`UNO_LAN_OPEN` 与 `UNO_DATA_DIR` 等环境变量。

### Docker

```bash
docker build -t uno-online .
docker run --rm -p 3000:3000 \
  -e PORT=3000 \
  -e HOST=0.0.0.0 \
  uno-online
```

也可以使用：

```bash
docker compose up --build
```

### Render / Railway / Fly.io / VPS

项目包含 `Dockerfile` 和 `render.yaml`。在支持 Docker 的平台上创建 Web 服务，暴露容器端口 `3000`，健康检查路径使用 `/api/health`。平台通常会自动注入 `PORT`；本项目默认读取 `PORT` 与 `HOST`。

若使用 Nginx 反向代理，需要同时转发 WebSocket：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

使用 HTTPS 域名访问，Socket.IO 会自动使用同源的 WSS。浏览器剪贴板功能也通常要求 HTTPS。

当前房间和对局保存在单实例内存中。部署时请使用**单个服务器实例**；如果需要多实例水平扩容，必须额外实现 Redis Socket.IO Adapter、粘性会话和共享房间状态，本项目没有虚假宣称已支持多实例。

公网部署还应持久化账号目录。Docker Compose 已配置 `uno-data` 命名卷；Render 等平台需要挂载持久磁盘并将 `UNO_DATA_DIR` 指向该磁盘，否则重新部署会丢失账号数据。

如果没有完成上述部署，当前状态只能本地或局域网运行，没有可公开访问的地址。

## 已确定的规则

规则冲突时以本节和需求中的明确说明为准，不引入额外积分、连击、皮肤或惩罚玩法。

### 牌库与开局

- 每局服务器生成 109 张牌：
  - 红、黄、蓝、绿 4 色，每色 19 张数字牌：0 各 1 张，1–9 各 2 张，共 76 张。
  - +2、跳过、反转各 8 张（每色 2 张），共 24 张功能牌。
  - 万能变色 4 张。
  - +4 万能 4 张。
  - 唯一 +10 牌 1 张。
- 合计 76 + 24 + 4 + 4 + 1 = 109 张。
- 每张牌都有唯一 `cardId`。+10 牌在创建牌库时生成一次；洗牌、发牌、摸牌、弃牌回收、刷新和重连都不会重新生成它。
- 2–6 名玩家各发 7 张，翻开第一张作为弃牌堆顶牌。
- 开场若翻到万能、+4 或 +10，服务器将该牌移到摸牌堆底部后继续翻牌，直到出现有色牌；所有牌仍计入 109 张。
- 开场跳过牌：首位玩家跳过。
- 开场反转牌：方向反转，由反方向的第一位玩家开始。
- 开场 +2：首位玩家摸 2 张并跳过。
- 开局特殊牌处理在引擎启动时完成，不会产生额外回合或重复发牌。

### 常规回合

- 可按当前颜色、相同数字或相同功能出牌；万能牌可在正常回合随时打出。
- 每回合最多打出一张牌。
- 玩家可以摸一张牌。摸到的牌可以打出时，本回合只能打这张新牌，也可以选择结束回合；摸到的牌不能打出时，服务器自动结束回合。
- 摸牌堆为空时，保留弃牌堆顶牌，把其余非 +10 牌洗回摸牌堆。+10 牌一旦进入弃牌堆，整局都不会回到摸牌堆。
- +2 与 +4 可以继续叠加；+10 是独立的即时惩罚牌，不参与 +2/+4 叠加。

### 双人规则

- 反转牌等同跳过牌，出牌者再次行动。
- 跳过牌使对手失去回合，出牌者再次行动。
- +2、+4 进入叠加响应窗口；对手可继续出 +2/+4，若不能或选择接受，则摸累计数量并失去回合。

### +2/+4 叠加与质疑

- 玩家打出 +2 或 +4 后，下一位玩家进入响应窗口：
  - 可以打出任意颜色的 +2 或 +4，把累计惩罚继续传给下一位；
  - 也可以选择“接受摸牌”，摸取当前累计数量并跳过回合；
  - 若 20 秒内没有响应，服务器自动按接受累计数量结算，避免对局永久卡住。
- 例：甲出 +2，乙出 +2，累计 4；丙出 +4，累计 8；丁若没有 +2/+4，则摸 8 张。
- 服务器记录每次 +4 出牌瞬间是否持有当前颜色牌。
- 若最后一次叠加的是 +4，目标可以质疑：
  - 质疑成立：最后一次 +4 的出牌者摸取当前累计的全部牌，质疑者继续行动；
  - 质疑不成立：质疑者摸取累计数量 + 2 张，并跳过回合；
  - 若最后一次叠加的是 +2，则不能质疑，只能继续叠加或接受。
- 若 +2/+4 是获胜的最后一张牌，对局直接结束，并按累计惩罚结算下家；不再开放质疑窗口。

### UNO 宣告

- 玩家打出牌后只剩一张时，服务器创建 UNO 窗口。
- 该玩家可在下一位玩家开始行动前宣告 UNO。
- 其他玩家也可在同一窗口内抓住未宣告者，成功后者摸 2 张。
- 一旦下一位玩家执行出牌、摸牌、结束回合或 +2/+4 响应等行动，窗口关闭；重复点击不会重复处罚。
- 宣告按钮只对刚刚打牌并剩一张的玩家开放。

### +10

- 打出后由服务器从红、黄、绿、蓝中等概率随机指定颜色，所有玩家收到同一权威颜色。
- 下一位玩家逐张摸 10 张并失去本回合，不参与 +2/+4 叠加。
- 摸牌过程中先耗尽摸牌堆，再按正常规则回收弃牌堆，但始终保留当前顶牌和所有 +10 牌。
- 如果所有可用牌仍不足 10 张，服务器只发实际存在的牌，记录 `deck_shortage` 事件，受罚者照样跳过回合；不复制牌、不进入死循环。
- 每局牌库、全部手牌和弃牌堆中的总牌数始终为 109，且每个 `cardId` 只出现一次。服务器在每次状态变更后执行完整性校验。

### 结束、退出与重连

- 玩家打出最后一张牌即获胜；若最后一张是 +2、+4 或 +10，先结算最终摸牌惩罚，再把全部剩余手牌数量同步给所有玩家。
- 房主可以开始新一局；新局会创建全新的 109 张牌库，并允许新的 +10 唯一标识。
- 断线玩家保留座位、手牌和当前对局，10 分钟内可凭本地会话凭证重连。刷新页面不会重新发牌。
- 房主掉线或离开时，房主自动转给下一位在线玩家。
- 对局中主动离开视为弃权，手牌移入弃牌堆；若只剩一名玩家，该玩家获胜。
- 玩家离线超过 10 分钟会弃权/释放座位；所有玩家离线 30 分钟后房间关闭。
- 对局开始后不再接受新玩家入座。

## 安全与一致性

- 每个玩家只有自己的手牌会发送到浏览器，其他玩家只公开手牌数量。
- 会话凭证仅返回给创建/加入者，服务器内存中保存 SHA-256 摘要。
- 出牌、摸牌、结束回合和 +2/+4 响应都携带当前 `turnNumber`；旧状态下的并发或过期请求会被拒绝。
- 每个操作携带 `actionId`，重复请求返回幂等结果，不会重复出牌或摸牌。
- 服务器验证房间、座位、当前回合、卡牌归属、颜色、手牌数量和游戏阶段。
- 牌库与弃牌内容不会发送给客户端，只发送数量、顶牌和当前颜色。

## 环境变量

```text
PORT=3000
HOST=0.0.0.0
CLIENT_ORIGIN=          # 仅前后端不同源部署时需要，多个来源用逗号分隔
VITE_SERVER_URL=        # 仅前端单独部署并连接另一域名时需要
UNO_LAN_OPEN=1          # 1 启动即开放；本地默认关闭
UNO_HOST_CONTROL=1      # 1 允许本机页面开关局域网；公网部署建议 0
UNO_DATA_DIR=./data     # 账号数据目录；部署时应指向持久卷
```

默认同源部署不需要设置 `CLIENT_ORIGIN` 或 `VITE_SERVER_URL`。
